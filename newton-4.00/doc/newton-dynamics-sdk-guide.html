A programmer's guide to the Newton Dynamics 4.00 SDK

Newton Dynamics is a cross-platform rigid body simulation library for real-time applications and game engines: bodies, collision shapes, joints, and a deterministic solver, exposed through a small set of C++ headers under sdk/. This guide walks through the module layout, the objects you'll touch most (ndWorld, ndBody, ndShapeInstance), and a minimal working example, drawn directly from the SDK source and the bundled sandbox demos.

01 — Setup

01Building the SDK

The SDK builds with CMake across Windows, macOS, and Linux. Newton's core has no third-party dependencies; only the bundled sandbox demo application pulls in OpenGL/GLFW for rendering.

Windows

CMake generates Visual Studio solutions for the SDK, demos, and language wrappers.

  • Core engine and packages: sdk/projects/
  • Asset conversion tool: applications/ndNewAsset/
  • Demo sandbox: applications/ndSandbox/

macOS

CMake generates an Xcode project for the SDK from the same sdk/projects/ entry point. The demo sandbox targets OpenGL and currently has no Metal backend, so it does not build on Apple platforms.

Linux

Unix makefiles are checked in alongside the CMake projects, but CMake is the recommended path. The core engine itself has zero external dependencies. To build the demo sandbox, install development packages for:

  • OpenGL
  • glfw3
  • glatter

These are available as -dev/-devel packages on most distributions, or can be built from source out of sdk/thirdParty/.

shellconfigure & build
# from the repository root
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release
Branch note

This guide documents the sdk/ tree on the dliw/newton-dynamics branch of JulioJerez/newton-dynamics, which corresponds to Newton core 4.00. It is a development branch — API surface can shift between commits. For the stable, long-supported line, see MADEAPPS/newton-dynamics, linked in Resources below.

02 — Layout

02Module map

The SDK is split into independent static libraries under sdk/. Most simulation code only needs dCore, dCollision, and dNewton; the rest are opt-in.

dCore

Math & foundation

Vectors, matrices, quaternions, containers (ndArray, ndTree), threading, smart pointers (ndSharedPtr), and the tinyxml dependency used for scene serialization.

dCollision

Bodies & shapes

ndBody, ndBodyKinematic, collision shapes (box, sphere, capsule, convex hull, height field, compound), broad-phase scene, and the player-capsule character controller.

dNewton

Solver & joints

ndWorld, ndBodyDynamic, the SIMD/SoA/AVX2 dynamics solvers, skeleton (articulated body) solver, and every joint type (hinge, slider, wheel, 6-DOF, vehicle joints, IK).

dModel

Higher-level models

Multi-body assemblies built on top of dNewton: animation blend trees, FBX mesh loading, and model-level body notification hooks.

dBrain

Machine learning

A self-contained neural-network / reinforcement-learning toolkit (layers, optimizers, CPU and OpenCL execution contexts) used by the sandbox's reinforcement-learning demos.

dRender

Reference renderer

An OpenGL-backed scene renderer (cameras, render passes, primitives) used to visualize the demos — not required to use the physics engine standalone.

dProfiler

Instrumentation

Optional Tracy-profiler integration for frame-level performance analysis.

dDependencies

Vendored libs

Third-party code built alongside the SDK, such as HACD for automatic convex decomposition.

The umbrella header dNewton/ndNewton.h pulls in the common simulation surface — world, bodies, every joint, IK solvers, and vehicle/model helpers — in one include, and is the fastest way to see the full public API at a glance.

03 — Walkthrough

03Getting started

Every simulation follows the same shape: create an ndWorld, add bodies with a shape and a mass, and step the world forward in a loop. The example below is adapted directly from the body-construction helpers in applications/ndSandbox/toolbox/ndPhysicsUtils.cpp and the ndBasicRigidBody demo, with the rendering calls stripped out so only the physics remain.

C++minimal_world.cpp
// 1. Create the world and give it a fixed timestep to step
ndWorld* world = new ndWorld();
world->SetSubSteps(2);

// 2. Build a static floor: a large flat box with zero mass
ndSharedPtr<ndShapeInstance> floorShape(
    new ndShapeInstance(new ndShapeBox(200.0f, 1.0f, 200.0f)));

ndSharedPtr<ndBody> floorBody(new ndBodyDynamic());
floorBody->SetMatrix(ndGetIdentityMatrix());
floorBody->GetAsBodyKinematic()->SetCollisionShape(**floorShape);
floorBody->GetAsBodyKinematic()->SetMassMatrix(0.0f, **floorShape); // mass 0 = static
world->AddBody(floorBody);

// 3. Build a dynamic sphere five units above the floor
ndMatrix origin(ndGetIdentityMatrix());
origin.m_posit.m_y = 5.0f;

ndSharedPtr<ndShapeInstance> ballShape(
    new ndShapeInstance(new ndShapeSphere(1.0f)));

ndSharedPtr<ndBody> ball(new ndBodyDynamic());
ball->SetMatrix(origin);
ball->GetAsBodyKinematic()->SetCollisionShape(**ballShape);
ball->GetAsBodyKinematic()->SetMassMatrix(1.0f, **ballShape); // mass 1.0 kg
world->AddBody(ball);

// 4. Step the simulation
const ndFloat32 timestep = 1.0f / 60.0f;
for (int frame = 0; frame < 120; ++frame)
{
    world->Update(timestep);
    world->Sync();  // block until the update finishes
    ndVector pos = ball->GetPosition();
}

delete world;

A few things worth internalizing from this example:

  • Shapes are shared, bodies own an instance. ndShapeInstance wraps a reference-counted ndShape (the geometric primitive itself), so the same box or convex hull can back many bodies cheaply. SetCollisionShape copies the instance onto the body.
  • Mass of 0 means static. SetMassMatrix(0.0f, shape) marks a body as immovable — the usual way to build floors, walls, and terrain.
  • Everything is reference-counted. Bodies, joints, and models are held in ndSharedPtr<T> and handed to the world with AddBody / AddJoint / AddModel; the world keeps its own reference until you call the matching Remove*.
  • Update is asynchronous. ndWorld::Update() can run the solver across a thread pool; call Sync() before reading back body transforms if you need the frame's result immediately.
04 — dCore

04Core math types

Everything in the physics API is built on a small set of SIMD-friendly value types defined in dCore. They behave like ordinary C++ value types — pass by value or const-reference, no manual lifetime management.

TypePurpose
ndVector4-wide float vector (x, y, z, w); used for positions, directions, forces, torques, and impulses.
ndMatrix4×4 transform matrix; body and joint frames are expressed as an ndMatrix (rotation + m_posit).
ndQuaternionRotation-only orientation, used where interpolation or compact storage matters (e.g. ndBody::GetRotation()).
ndFloat32 / ndInt32 / ndUnsigned32Fixed-width scalar aliases used throughout the API instead of raw float/int, to keep behavior identical across platforms.
ndSharedPtr<T>Intrusive-style reference-counted smart pointer used for bodies, joints, models, and shape instances.
ndArray<T> / ndTree<T>Lightweight dynamic array and balanced-tree containers used internally and in public collection APIs (e.g. ndBodyList, ndJointList).

Two free helpers you'll reach for constantly: ndGetIdentityMatrix() for a neutral transform, and constructing an ndMatrix from an ndQuaternion plus a position when you need an arbitrary starting orientation.

05 — dNewton

05ndWorld

ndWorld is the simulation container: it owns the broad-phase scene, the solver, and every body, joint, and model added to it. One ndWorld instance is a complete, independent simulation.

MethodWhat it does
Update(ndFloat32 dt)Advances the simulation by dt. May run asynchronously across the thread pool.
Sync() constBlocks until the in-flight Update() has finished.
AddBody / RemoveBodyRegisters or unregisters an ndSharedPtr<ndBody> with the world.
AddJoint / RemoveJointRegisters or unregisters a bilateral constraint (any joint in dJoints).
AddModel / RemoveModelRegisters a higher-level ndModel (e.g. a vehicle or articulated ragdoll).
SetThreadCount(n)Sizes the internal worker thread pool used by the solver and broad-phase.
SetSubSteps(n)Number of solver sub-steps per Update() call, trading CPU time for stability/accuracy.
SelectSolver(mode)Chooses between ndStandardSolver, ndSimdSoaSolver, and ndSimdAvx2Solver.
RayCast / ConvexCastCasts a ray or a convex shape through the scene, reporting hits via a notify callback.
BodiesInAabb(cb, min, max)Broad-phase query for every body overlapping an axis-aligned box.
GetBodyList / GetJointList / GetContactListRead-only views over everything currently tracked by the world.
06 — dCollision / dNewton

06Bodies

Bodies form a small hierarchy. You'll almost always construct the concrete leaf type, but the shared behavior lives further up.

ClassRole
ndBodyAbstract base: transform (GetPosition, GetRotation, SetMatrix), velocity, notify callback.
ndBodyKinematicAdds collision: shape instance, mass matrix, sleep state, contact/joint attachment, AABB.
ndBodyDynamicConcrete simulated rigid body — forces, torque, and impulses are integrated by the solver every step.
ndBodyKinematicBaseKinematic (script-driven) body: participates in collision but is moved directly rather than by forces.
ndBodyPlayerCapsulePurpose-built capsule body for first/third-person character controllers.
ndBodyTriggerVolumeNon-colliding volume used to detect overlap events, e.g. gameplay trigger zones.
ndBodySphFluidSPH-based particle fluid body.

Common ndBodyKinematic operations

MethodWhat it does
SetCollisionShape(shape)Attaches an ndShapeInstance to the body.
SetMassMatrix(mass, shape)Derives inertia from the shape and assigns mass; 0.0f makes the body static.
SetForce / SetTorqueApplies a force or torque for the current step (re-applied every frame if you want continuous force, e.g. gravity or thrust).
AddImpulse(vel, point, dt)Applies an instantaneous impulse at a world-space point.
SetOmega / SetVelocityDirectly sets angular / linear velocity.
GetAutoSleep / SetAutoSleepControls whether the body is allowed to go dormant when at rest, to save CPU.
SetSkeleton / GetSkeletonAssigns the body to an ndSkeletonContainer for articulated (multi-body chain) solving.
Gotcha

Setting force or torque with SetForce/SetTorque only affects the next solver step — Newton does not remember "constant" forces between calls. Gravity, thrusters, and similar continuous forces are typically applied from an ndBodyNotify::OnApplyExternalForce override, which the solver calls every sub-step.

07 — dCollision

07Collision shapes

A body's collidable geometry is an ndShapeInstance wrapping a reference-counted ndShape. Because the shape is shared and reference-counted, it's normal to build one shape and reuse it across hundreds of bodies (e.g. a crate box or a debris chunk).

ShapeNotes
ndShapeBoxAxis-aligned box primitive, defined by size.
ndShapeSphereSphere primitive, defined by radius.
ndShapeCapsule / ndShapeCylinder / ndShapeCone / ndShapeChamferCylinderRounded convex primitives.
ndShapeConvexHullConvex hull generated from an arbitrary point cloud.
ndShapeCompoundAggregates multiple child shapes into one rigid collidable, e.g. an L-shaped part.
ndShapeStatic_bvh / ndShapeStaticMeshStatic triangle-mesh collision (level geometry) backed by a bounding-volume hierarchy.
ndShapeHeightfieldRegular-grid heightfield for terrain.
ndShapeStaticProceduralMesh / ndShapeUserDefinedImplicitExtension points for custom or procedurally generated collision.
ndShapeNullEmpty shape — a body that occupies space in the world but never collides.

Automatic convex decomposition of concave meshes into a compound of hulls is available via the vendored HACD library in dDependencies/hacd.

08 — dNewton / dJoints

08Joints & constraints

Joints connect two ndBodyKinematic instances (a child and a parent — pass nullptr as parent to anchor to the static world). All joints derive from ndJointBilateralConstraint and are registered with world->AddJoint(...).

JointConstrains
ndJointHinge1 rotational DOF about a pin axis, with optional limits and spring-damper.
ndJointSlider1 translational DOF along an axis.
ndJointCylinder1 rotational + 1 translational DOF along the same axis.
ndJointDoubleHinge / ndJointSlidingHinge2-DOF rotational combinations, e.g. universal-joint style linkages.
ndJointSphericalBall-and-socket (3 rotational DOF).
ndJointFix6dofFully fixed (0 DOF) — welds two bodies together while still reporting reaction forces.
ndJointFixDistanceKeeps two points at a fixed distance, like a rope segment or rod.
ndJointGear / ndJointPulleyCouples motion between two other joints with a fixed ratio.
ndJointWheel / ndJointRollerSuspension-style joints used by the vehicle model.
ndJointUpVectorConstrains a body axis to stay aligned with a world direction (e.g. keep a character upright).
ndJointFollowPathConstrains a body to travel along a path.
ndJointKinematicControllerDrags a body toward a target frame — the basis for mouse-pick / grab interactions.
ndJointDryRollingFrictionAdds rolling-resistance damping, typically to wheels.

Inverse kinematics

The dIkSolver module layers IK on top of the same joint machinery: ndIkJointHinge, ndIkJointSpherical, ndIkJointDoubleHinge, ndIk6DofEffector, and ndIkSwivelPositionEffector, driven by an ndIkSolver instance.

C++hinge_joint.cpp
// pin frame: world-space matrix whose front axis is the hinge axis
ndMatrix pin(ndGetIdentityMatrix());
pin.m_posit = childBody->GetPosition();

ndSharedPtr<ndJointBilateralConstraint> hinge(
    new ndJointHinge(pin, childBody->GetAsBodyKinematic(), nullptr));

ndJointHinge* hingePtr = (ndJointHinge*)*hinge;
hingePtr->SetAsSpringDamper(0.02f, 1500.0f, 40.0f);
world->AddJoint(hinge);
09 — Interaction

09Queries & callbacks

Newton reports events through small notify/callback interfaces you subclass, rather than a global event bus.

InterfaceUsed for
ndBodyNotifyPer-body hook for applying external forces (OnApplyExternalForce) and reacting to transform changes.
ndContactNotifyWorld-level hook for contact creation/removal and material selection between shape pairs.
ndRayCastNotifyReceives hits from ndWorld::RayCast.
ndConvexCastNotifyReceives hits from ndWorld::ConvexCast.
ndBodiesInAabbNotifyReceives results from ndWorld::BodiesInAabb.

Each is a small abstract class: override the relevant virtual method, pass an instance to the query, and the world calls back into it synchronously during the query.

10 — Reference

10Common patterns

Ownership

Wrap anything handed to the world — bodies, joints, models, shape instances — in ndSharedPtr<T>. The world holds its own reference once added; letting your local ndSharedPtr go out of scope afterward is safe.

Static vs. dynamic

There's no separate "static body" class — a static object is simply an ndBodyDynamic (or ndBodyKinematic) with SetMassMatrix(0.0f, shape).

Stepping on a fixed timestep

Accumulate real elapsed time and call world->Update(fixedDt) in a fixed-size loop, calling Sync() once per frame before reading back transforms for rendering — the same pattern used by ndDemoEntityManager in the sandbox application.

Threading

Size the solver's thread pool once at startup with SetThreadCount; the solver and broad-phase parallelize internally, so application code generally doesn't need its own locking around world queries made between Update() calls.
