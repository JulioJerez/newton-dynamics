File Formats

The editor natively reads and writes .nd files, and can import meshes and physics from FBX and URDF sources.

Native Format — .nd

The .nd format is Newton Dynamics' own binary/XML serialization. It stores the complete scene graph including:

  • Node hierarchy with names, transforms, and visibility flags
  • Geometry (vertex positions, normals, UVs, materials)
  • Rigid body data (mass, inertia, CoM, damping)
  • Collision shape types and parameters
  • Structural joints with all parameters and local frames
  • Loop joint lists and colliding-pair lists
  • Custom properties on each node
  • Modifier settings

Saving

File → Save writes back to the path shown in the window title bar. File → Save As opens a system dialog to choose a new .nd path. The extension is appended automatically if omitted.

Loading

File → Load opens a dialog filtered to *.nd files (also accepts all files). The current scene is replaced entirely and the undo history is cleared. The camera repositions to frame the loaded mesh.

Window title: After loading, the title bar updates to show the full file path: Newton Dynamics X.XX → model path: /path/to/file.nd

FBX Import

Use File → Import fbx to bring in an FBX file. The importer reads geometry, materials, and the node hierarchy. Physics data is inferred automatically from node name suffixes.

After import the scene replaces the current one (undo history is cleared). The camera repositions to frame the imported model.

FBX import is not a round-trip format. Physics data created in the editor is stored in .nd files, not in FBX. Re-importing the same FBX will discard any physics you have set up. Always save to .nd once physics is configured.

URDF Import

Use File → Import urdf to load a Unified Robot Description Format file. The importer parses the XML and constructs a full ndModelArticulation, then converts it into the editor's mesh/body/joint scene graph.

What gets imported

  • Links — each <link> becomes a mesh node with a rigid body.
  • Inertial — mass and full inertia tensor (ixx, ixy, ixz, iyy, iyz, izz) are read.
  • Collision — primary collision shape per link. Multiple <collision> elements produce a Compound shape.
  • Visual — mesh geometry from .stl or .obj files referenced in <visual> tags. If no visual is found, the collision shape is used as a stand-in.
  • Joints — converted to structural Newton joints (see table below).
  • Materials — diffuse colors and texture names are parsed from <material> tags and applied to visual materials.

Coordinate system

URDF uses Z-up; Newton uses Y-up. The importer applies a ndPitchMatrix(−π/2) rotation to the entire model after loading to convert the coordinate frame automatically.

Newton URDF extensions

Standard URDF does not support spring-damper parameters or Newton-specific joint types. The importer reads a <newton> child element inside joints to access these:

<joint name="arm_hinge" type="continuous">
  <parent link="shoulder"/>
  <child  link="upper_arm"/>
  <newton
    springPD="500"
    damperPD="20"
    regularizer="0.001"/>
</joint>
<joint name="wrist" type="floating">
  <newton replaceWith="ndIkJointSpherical"/>
</joint>

URDF Mesh Files

URDF visual and collision sections can reference external mesh files via <geometry><mesh filename="…"/></geometry>. The importer supports:

FormatUsed forNotes
.stlVisual and collisionBinary STL. Parsed triangle by triangle with normals. Used as convex hull for collision.
.objVisual onlyWavefront OBJ with normals and UVs. Associated .mtl is parsed for diffuse color and texture name.

Files are located by searching the directory of the URDF file first, then a secondary search path. The filename is compared case-insensitively. If a file is not found, the node receives a Null collision shape and no visual geometry — a warning is printed to the trace log.

Scale attribute

The scale attribute on <mesh> is supported:

<mesh filename="arm.stl" scale="0.001 0.001 0.001"/>
<!-- converts millimeters to meters -->

Newton shape replacements in URDF collision

URDF's cylinder collision shape can be mapped to a Newton capsule by adding:

<geometry>
  <cylinder length="0.2" radius="0.05"/>
  <newton replaceWith="capsule"/>
</geometry>

Media / Asset Search Path

The editor resolves relative asset paths (textures, mesh files) by searching upward from the executable location for an applications/media/ directory. On Linux it uses /proc/<pid>/exe to find the executable; on macOS it uses the app bundle path; on Windows it uses GetModuleFileNameA.

For URDF imports, the directory containing the .urdf file and the path returned by the media search are both checked when resolving mesh filenames.

Tip: If textures appear missing after import, place them in applications/media/ relative to the editor executable, or in the same directory as your URDF/FBX file.
