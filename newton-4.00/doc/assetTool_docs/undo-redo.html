Undo / Redo

The editor uses a command-based undo/redo system. Every significant edit pushes a snapshot onto a linear stack. You can step backward and forward through that stack using the toolbar buttons.

How It Works

Each destructive operation pushes two commands onto the undo stack — one before the edit and one after:

  1. Push a "before" snapshot capturing the current state.
  2. Apply the change.
  3. Push an "after" snapshot capturing the new state.

When you undo, the editor steps one position back in the stack and calls Undo() on that command, which restores the saved state. When you redo, it steps forward and calls Undo() on the next command (which is the "after" snapshot — restoring the post-edit state).

Design note: Both undo and redo use the same Undo() method. The "before" and "after" snapshots are stored as consecutive entries; stepping backward restores the "before" state, stepping forward restores the "after" state.

The Undo Stack

The stack is a doubly-linked list with a pointer (m_currentCommand) tracking your current position:

oldest
before: add body
after: add body
before: set mass = 5
← current
after: set mass = 5
before: change shape
newest
after: change shape

The greyed-out entries above the current position are "future" states that exist because you have undone some steps. If you make a new edit while in this state, all future entries are discarded and the new edit is appended — standard linear undo behavior.

Toolbar buttons

ButtonBehavior
undoSteps one position backward and restores the "before" snapshot. The current selection is restored to the node named in that snapshot.
redoSteps one position forward and restores the "after" snapshot. Selection is similarly restored.

Both buttons do nothing if the stack is empty or if there is no previous/next entry to move to.

Deduplication

Before appending a new command, the editor compares it to the current top of the stack using the operator!= method. If the new state is identical to the current state (e.g., you typed the same value twice, or pressed Enter on an unchanged field), the command is silently dropped and the stack is not grown.

Each command type implements its own equality check:

  • MeshNode — full node-by-node comparison of the entire mesh tree.
  • Shape — compares the ndMeshShapeInstance struct.
  • RigidBody — compares mass, inertia, damping, and center-of-mass vectors.
  • StructuralJoint — compares joint type and all joint parameters.
  • LoopJoint — compares count and identity of all loop joints in the container.
  • CollidingPairs — compares count and pointer identity of all pairs.

Command Types

Six distinct command classes cover all editor operations:

CommandWhat it snapshots
MeshNode A full deep clone of the entire mesh tree (CreateClone()). Used for node transforms, name changes, adding/removing nodes, material edits, custom properties, and modifier changes. The most expensive snapshot — clones the whole scene.
Shape A copy of the selected node's ndMeshShapeInstance. Used for all collision shape edits (type, dimensions, local transform, scale).
RigidBody A duplicate of the ndMeshBodyDynamic. Used for mass, inertia, damping, CoM, step-size edits.
StructuralJoint A duplicate of the ndMeshJoint object. Used for all structural joint edits (type changes, frame offsets, spring/damper, limits).
LoopJoint Deep copies of all loop joints in the loop-joint container. Used when adding/removing loop joints and editing any loop joint parameter.
CollidingPairs The full list of shared pointers to colliding pair entries. Used when adding or removing colliding pairs.

What Is Covered

The following operations are undoable:

  • Node name changes
  • Node transform (position/rotation) and geometry transform changes
  • Visibility toggle
  • Adding and cloning nodes
  • Adding and removing rigid bodies
  • All collision shape type changes and parameter edits
  • All structural joint type changes and parameter edits
  • All loop joint additions, removals, and parameter edits
  • Adding and removing colliding pairs
  • Material property edits (color, texture, opacity)
  • Custom property additions, removals, type changes, and value edits
  • Modifier type changes and parameter edits
  • All mesh tool operations (resize, rotate, normalize mass)

Limitations

Stack is cleared on scene load. Opening a new file, importing FBX/URDF, or using File → New calls m_undoRedo.Clear(). There is no undo across file operations.
  • There is no configurable maximum stack depth — the list can grow indefinitely for long editing sessions.
  • Viewport camera moves are not undoable.
  • Render mode and Options-panel toggles are not undoable.
  • The delete node button in the Mesh Node section is currently a stub (ndTrace only) — it does not perform a deletion and therefore does not add to the undo stack.
