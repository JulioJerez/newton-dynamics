Interface & Navigation

The toolbar, the outliner, and how the camera and selection behave in the 3D viewport.

2Viewport camera & selection

Mouse behavior in the 3D viewport, while nothing else has input focus:

Mouse controls

Right drag

A left click that doesn't drag performs a raycast pick and calls the same selection logic as clicking a row in the outliner, so the two stay in sync. Selection is suppressed while Lock Selection is on, which is useful once you've got the right node selected and don't want a stray click to lose it.

Two picking modes Options → show mesh skeleton switches the raycast target between mesh geometry and skeletal bones. With bones enabled, clicking picks the nearest bone segment to the cursor ray instead of a render mesh triangle — useful on rigs where the visual mesh doesn't closely follow the skeleton.

3Outliner Panel

A tree view of the current asset's mesh hierarchy, docked on the left.

  • Collapse all collapses every branch to a flat top‑level list.
  • Clicking a row selects that node (or, while adding a loop joint / colliding pair / target reference, assigns it as the sub‑selection instead — see Joints & Colliding Pairs).
  • Nodes that carry data show extra bullet rows underneath: joint, geometry, rigidBody.
  • Two special top‑level entries always appear: the closed‑loop constraint list and the colliding‑pairs list for the whole asset.

4Selection & sub‑selection

The editor tracks two selections at once: the current selection (what the properties panel shows) and, in specific workflows, a sub‑selection — a second node picked while linking two things together (a loop joint's other body, a colliding pair's partner, a look‑at/IK target, a custom property's referenced node). While a sub‑selection mode is active, clicking in the viewport or outliner feeds that picker instead of changing the main selection.

5Undo & redo

Almost every edit — transforms, joint parameters, shape parameters, adding or deleting nodes — pushes an undo snapshot before and after the change. Undo/redo also restores whatever was selected at that point in history, so stepping back through edits re‑focuses the properties panel on the node you were editing.

Scope of undo Snapshots are taken per‑operation around the widget you're editing (a single mesh node, the loop‑joint list, the colliding‑pairs list, or a rigid body). Running one of the Mesh Tools is also wrapped in a single undo step, so a resize or rotation can be undone in one action even though it touches many nodes internally.
